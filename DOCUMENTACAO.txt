1. VISÃO GERAL E ADERÊNCIA AO TEMA
----------------------------------------------------------------

A plataforma Lobo-guará Tech premia pessoas que praticam ações
ambientais. Cada ação enviada vira uma "postagem" com link de
evidência, que fica PENDENTE até a moderação aprovar ou rejeitar, e
gera pontos para o usuário.

O programa em Python é um segundo canal de acesso a esses mesmos
dados: o que é registrado, alterado ou excluído por ele fica gravado no
mesmo banco usado pela API Java, e o que foi cadastrado pela plataforma
(usuários, comunidades e postagens) é lido pelo programa. Os dados são
relevantes para o projeto porque são exatamente os do desafio: ações
sustentáveis, pontuação e ranking.

O código é dividido em 6 arquivos:

  - main.py     -> ponto de entrada; organiza o fluxo entre os menus.
  - menu.py     -> tudo que aparece na tela e tudo que o usuário
                   digita (menus, tabelas, perguntas).
  - dados.py    -> estruturas de dados (períodos, níveis de impacto),
                   validações, cálculo de pontos, filtros e
                   ordenações. Não usa print() nem input().
  - banco.py    -> acesso ao Oracle (conexão e CRUD). Não usa print()
                   nem input().
  - api.py      -> consumo da API pública (GET). Não usa print() nem
                   input().
  - exportar.py -> geração dos arquivos JSON. Não usa print() nem
                   input().

Bibliotecas: oracledb (banco) e requests (API) - ver requirements.txt;
json, os, datetime e textwrap fazem parte da biblioteca padrão.

2. COMO EXECUTAR
----------------------------------------------------------------

1) Instalar as dependências:
       pip install -r requirements.txt

2) Criar um arquivo .env (copiar o .env.example) com as credenciais
   do Oracle:
       DB_HOST=oracle.fiap.com.br
       DB_PORT=1521
       DB_SID=ORCL
       DB_USER=<usuário>
       DB_PASSWORD=<senha>
   O arquivo .env guarda a senha do banco e não é versionado (está
   no .gitignore).

3) Rodar:
       python main.py

Tabelas usadas, as mesmas da API Java: T_LGT_USUARIO,
T_LGT_COMUNIDADE, T_LGT_USUARIO_COMUNIDADE e T_LGT_POSTAGEM.

3. FLUXO DE FUNCIONAMENTO
----------------------------------------------------------------

3.1. Abertura
   O programa abre a conexão com o Oracle e mostra o menu principal.
   Se o banco não responder ou se faltar o .env, mostra a mensagem de
   erro e encerra. A conexão é fechada no final, no bloco finally.

3.2. Identificação
   O usuário só é identificado na primeira vez que escolhe uma opção
   que precisa dele (1, 2 ou 3). O sistema pede o CPF (11 números),
   procura no banco e, se achar, dá boas-vindas. Se o usuário
   participa de comunidades, escolhe em qual vai registrar. Se o CPF
   não existe, avisa para se cadastrar pelo site. Digitar 0 volta.
   O CPF nunca é exibido nas telas.

3.3. Menu principal
     0. Sair
     1. Registrar pontos
     2. Gerenciar ações (submenu do CRUD)
     3. Relatórios (submenu)
     4. Trocar de usuário
     5. Consultar API pública (submenu)

3.4. Opção 1 - Registrar pontos (INSERT)
   a) Mostra os períodos (1 a 7 dias, 8 a 15 dias, 16 a 30 dias) e
      pede o período inicial. Se havia progresso salvo, pergunta se
      continua de onde parou ou recomeça.
   b) Para cada dia, pergunta se houve ação ambiental:
        - Não: o dia vale 0 pontos e não é gravado no banco.
        - Sim: pede o nível de impacto (Alto 1,06 / Médio 0,66 /
          Baixo 0,16), o nome da ação e o link da evidência (precisa
          começar com http:// ou https://). Calcula os pontos do dia
          respeitando os limites (100 no total, 68 pelos dias e
          31,80 pelas ações) e grava a ação no banco como postagem
          PENDENTE.
   c) Se o banco recusar o registro, o cálculo do dia é desfeito.
   d) O ciclo termina ao chegar em 100 pontos ou no dia 30; mostra o
      resumo final. Se o usuário parar antes, o progresso fica salvo
      para continuar depois.

3.5. Opção 2 - Gerenciar ações (CRUD no banco)
     1. Inserir   - registra uma ação, no mesmo fluxo da opção 1
                    (CREATE).
     2. Listar    - mostra as postagens do usuário em uma tabela
                    (READ).
     3. Buscar    - pede o nome exato da ação, sem diferenciar
                    maiúsculas de minúsculas, e mostra as encontradas
                    (READ).
     4. Atualizar - mostra a lista numerada, o usuário escolhe pela
                    posição e troca o nome da ação (UPDATE).
     5. Excluir   - mostra a lista numerada, o usuário escolhe pela
                    posição, vê os dados e confirma com s ou n
                    (DELETE).
     6. Voltar
   Regra de negócio: só postagens PENDENTES podem ser atualizadas ou
   excluídas; depois da moderação os pontos já foram decididos. Os
   pontos e o link não são editáveis; para mudar, exclui-se e
   registra-se de novo.

3.6. Opção 3 - Relatórios
     1. Ver registros - lista as postagens do usuário.
     2. Filtrar por status - mostra só as PENDENTE, APROVADO ou
        REJEITADO.
     3. Ações por pontos - ordena do maior para o menor.
     4. Exportar ações do banco (JSON) - gera o arquivo
        crud_usuario_<id>.json com as postagens do usuário.
     5. Exportar minhas respostas (JSON) - gera o arquivo
        respostas_usuario_<id>.json com o que foi respondido em
        "Registrar pontos" nesta sessão.
     6. Voltar
   Os arquivos JSON são gravados na pasta "exportacoes" (criada
   automaticamente), com acentos preservados e indentação. A data da
   exportação aparece no formato dia/mês/ano hora:minuto:segundo.

3.7. Opção 5 - Consultar API pública (consumo de API)
     1. Ranking de usuários - faz GET /usuarios e ordena por pontos,
        do maior para o menor.
     2. Postagens de uma comunidade - faz GET /comunidades e GET
        /postagens; o usuário escolhe a comunidade e vê as postagens
        dela.
     3. Voltar
   Não exige identificação. O Render gratuito pode levar mais de 1
   minuto para "acordar" na primeira chamada; por isso o tempo limite
   da requisição é de 120 segundos.

3.8. Opção 4 e 0
   4 troca de usuário (limpa a sessão e o progresso); 0 encerra.

4. REQUISITOS DA SPRINT E ONDE ESTÃO NO CÓDIGO
----------------------------------------------------------------

- Menus e submenus de acesso ao CRUD:
    main.py (executa_menu_principal, executa_menu_crud,
    executa_menu_relatorios, executa_menu_api) e menu.py (menu_*).

- Um exemplo de cada operação do CRUD, integrado ao banco:
    banco.py: inserir_postagem (CREATE), listar_postagens e
    buscar_postagens (READ), atualizar_postagem (UPDATE),
    excluir_postagem (DELETE).

- Exportação dos dados para JSON:
    exportar.py (monta_exportacao_crud, monta_exportacao_respostas,
    salvar_json) e menu.py (exportar_*_interativo).

- Consumo de API pública:
    api.py (buscar_json, listar_usuarios_api, listar_comunidades_api,
    listar_postagens_api), usando requests.

- Funções para organizar, filtrar e ordenar dados em listas de
  dicionários e tuplas:
    dados.py (filtrar_por_status, registros_por_pontos,
    ranking_de_usuarios, filtrar_por_comunidade).

- Tratamento de erros (try / except / else / finally):
    banco.py (rollback no except, commit no else, cursor.close() no
    finally), api.py (Timeout, ConnectionError, HTTPError, JSON
    inválido e outras falhas do requests), exportar.py
    (OSError/TypeError), main.py (Ctrl+C e Ctrl+D encerram o sistema
    com uma mensagem) e menu.py
    (atualizar_registro_interativo e excluir_registro_interativo).
    Os erros são convertidos nas exceções próprias ErroBanco, ErroApi
    e ErroExportacao, com mensagens amigáveis; o programa não fecha
    por causa delas.

- Validação de dados (entrada e processamento):
    dados.py (cpf_formato_valido, url_valida, nome_valido,
    inteiro_valido, periodo_valido, nivel_impacto_valido) e os
    "pede_*" de menu.py, que repetem a pergunta até receber um valor
    válido. As consultas ao banco usam parâmetros nomeados (:cpf,
    :id_usuario...), nunca texto concatenado, evitando SQL injection.


----------------------------------------------------------------
5. RESUMO DAS FUNÇÕES
----------------------------------------------------------------

5.1. dados.py (dados e regras de negócio - sem print/input)

   Dados: periodos, niveis_impacto, respostas_usuario, progresso,
   LIMITE_TOTAL, LIMITE_DIAS e LIMITE_ACOES.

   - nome_valido............: texto não pode ser vazio.
   - cpf_formato_valido.....: 11 números, não todos iguais.
   - inteiro_valido.........: diz se um texto vira inteiro.
   - periodo_valido.........: período é 1, 2 ou 3.
   - nivel_impacto_valido...: o nível de impacto existe.
   - url_valida.............: link começa com http(s):// e não tem
                              espaços.
   - base_diaria............: pontos básicos do dia (1, 2 ou 3).
   - peso_do_nivel..........: peso de um nível de impacto.
   - nome_do_nivel..........: nome de um nível de impacto.
   - calcula_pontos_dia.....: pontos do dia respeitando os limites.
   - filtrar_por_status.....: registros com um status.
   - registros_por_pontos...: ordena do maior para o menor ponto.
   - ranking_de_usuarios....: ordena usuários por saldo de pontos.
   - filtrar_por_comunidade.: postagens de uma comunidade.

5.2. banco.py (Oracle - sem print/input)

   - carregar_env...........: lê o .env para as variáveis de ambiente.
   - conectar...............: abre a conexão (ErroBanco se falhar).
   - buscar_usuario_por_cpf.: procura o usuário pelo CPF.
   - listar_comunidades_do_usuario: comunidades em que ele é membro.
   - inserir_postagem.......: CREATE (postagem PENDENTE).
   - listar_postagens.......: READ de todas as postagens do usuário.
   - buscar_postagens.......: READ por nome exato da ação.
   - atualizar_postagem.....: UPDATE do nome (só PENDENTE).
   - excluir_postagem.......: DELETE (só PENDENTE).
   - montar_postagem........: converte uma linha do SELECT em dict.
   - montar_lista_de_postagens: converte várias linhas em uma lista de
                                dicts, usando montar_postagem.

5.3. api.py (consumo da API - sem print/input)

   - buscar_json............: GET genérico com tratamento de erros.
   - listar_usuarios_api....: GET /usuarios.
   - listar_comunidades_api.: GET /comunidades.
   - listar_postagens_api...: GET /postagens.
   A API devolve JSON em camelCase (nmCompleto, ctTexto, ptGerado...);
   as funções convertem para os mesmos dicts usados no resto do
   sistema (nome, acao, pontos...).

5.4. exportar.py (JSON - sem print/input)

   - monta_exportacao_crud......: dict com usuário, data, total de
                                  registros, total de pontos e a lista.
   - monta_exportacao_respostas.: dict com usuário, comunidade, resumo
                                  e respostas dia a dia.
   - salvar_json................: grava o arquivo em "exportacoes".

5.5. menu.py (interface - telas, input() e mensagens)

   - pausar, pergunta_sim_nao, pede_numero_da_lista: perguntas
     reutilizáveis.
   - identificar_usuario, pede_cpf_valido, pede_usuario_cadastrado,
     escolhe_comunidade: identificação por CPF.
   - mostra_*: tabelas com borda (períodos, níveis, registros). A
     tabela de registros usa textwrap para quebrar ações longas sem
     desalinhar a borda.
   - registrar_pontos e suas auxiliares (inicia_novo_ciclo,
     retoma_ciclo, registra_dia, decide_proximo_passo...): fluxo de
     registro dia a dia.
   - *_registro_interativo: listar, buscar, atualizar e excluir.
   - relatorio_*_interativo e exportar_*_interativo: relatórios e JSON.
   - ranking_api_interativo e postagens_da_comunidade_api_interativo:
     telas da API.
   - menu_principal, menu_crud, menu_relatorios, menu_api: menus.

5.6. main.py (orquestração)

   - main...................: abre a conexão, roda o sistema e fecha a
                              conexão no finally.
   - executa_menu_principal.: loop do menu principal e da sessão.
   - executa_menu_crud / executa_menu_relatorios / executa_menu_api:
     loops dos submenus.
   - garante_identificacao..: identifica o usuário quando necessário.
